# КиноНавигатор

Учебный прототип рекомендательной системы фильмов с агентным потоком.

## Тема

«КиноНавигатор: система рекомендаций фильмов с объяснением выбора».

Пользователь указывает жанры и ограничения, например: «Посоветуй фантастику без ужасов». Система извлекает предпочтения, получает кандидатов от рекомендательного алгоритма, проверяет их по каталогу и исключает запрещённые жанры.

## Цель

Сравнить несколько подходов к рекомендациям фильмов и связать их с агентным интерфейсом, который обрабатывает запрос пользователя, проверяет рекомендации и объясняет результат.

## Алгоритмы в прототипе

- Popularity baseline — ранжирование по оценкам из учебных данных.
- Content-based — подбор по совпадению жанров.
- Item-item collaborative filtering — подбор по сходству оценок фильмов.
- Hybrid — комбинирование нескольких алгоритмов.

## Данные и ограничения

В текущей версии используется небольшой демонстрационный каталог и учебные оценки, встроенные в `app.py`. Это не MovieLens и не реальные данные сервиса.

Демонстрационные метрики на таком каталоге нельзя интерпретировать как качество рекомендаций для реальной аудитории. Для полноценной оценки нужно отдельно подготовить датасет, разделить данные на обучение и тест и проверить алгоритмы на тестовой части.

## Установка и запуск

Проект проверяется в виртуальном окружении Python. Основная версия использует стандартные библиотеки Python.

Запуск приложения:

    python app.py

Для ручной проверки введи запрос, например:

    Посоветуй фантастику без ужасов

Для демонстрационной оценки введи:

    eval

## Тесты

Запуск тестов:

    python -m unittest -v

Последняя проверка: 9 тестов завершились успешно (`OK`).

## Память и логи

В прототипе предусмотрены функции работы с SQLite-профилем пользователя.

Файл базы создаётся в `data/profiles.sqlite`. Не добавлять файл базы в общий Git-репозиторий.

События приложения записываются в `logs/traces.jsonl`. Это локальный журнал прототипа, а не полноценная платформа observability.

## LLM и агентные компоненты

На текущем этапе часть обработки запроса выполняется локальным Python-разборщиком. Это позволяет проверять базовую логику без внешней модели.

Подключение LLM, выбор модели, маршрутизация между моделями и подключение фреймворка должны быть зафиксированы после фактической проверки. Не считать их реализованными до успешного запуска.

## Изоляция

Docker в проекте не используется по требованию преподавателя.

Планируемый вариант для изолированного запуска — отдельная виртуальная машина. Конфигурация VM, запуск приложения и ограничения окружения будут описаны после практической проверки.

Агенту не следует предоставлять произвольный доступ к терминалу, операционной системе или файлам пользователя. Инструменты нужно ограничить заранее заданными функциями приложения.
